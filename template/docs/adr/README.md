# Architecture Decision Records

Create an ADR only for a durable decision that materially constrains future design and whose rationale is not obvious from the resulting architecture.

Do not create ADRs for ordinary implementation choices, temporary workarounds or task completion.

Suggested format:

```markdown
# ADR NNNN — Decision title

Status: accepted
Date: YYYY-MM-DD

## Context

## Decision

## Consequences

## Alternatives considered
```

Accepted ADRs are durable; supersede rather than silently rewrite material historical rationale.
