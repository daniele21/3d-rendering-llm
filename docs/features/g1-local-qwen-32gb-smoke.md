# Local Qwen first experiment — Apple Silicon 32 GB

Status: experimental **stacked on G1 native-name normalizer PR #66**.
Do not treat this as a successful native/local model benchmark until the
operator actually runs it and audits all private scene artifacts.
No paid API calls are made by this workflow, no cloud fallback is allowed,
and the original Luna source/results stay unchanged.

## Chosen model and RAM bounds

- Model: [Ollama qwen3-coder:30b-a3b-q4_K_M](https://ollama.com/library/qwen3-coder/tags).
  30.5B total parameters, 3.3B active, **19 GB Q4_K_M** model archive.
  Model file size is **not** the full RAM resident footprint.
- Hardware: 32 GB unified Apple Silicon, macOS. Start with **8192**
  context tokens, **4096** maximum output tokens, temperature **0.1**,
  seed **42**, and **one** generation at a time.
- The loopback-only adapter always uses `127.0.0.1:11434/api/chat`
  with `stream=false` and `keep_alive=0`: model weights unload
  before Blender is invoked, trading repeated load latency for safer memory.
  No remote/custom URL, auth, proxy, cloud-tag or silent model substitution.
- Use `ollama ps`, `memory_pressure -Q` and `sysctl vm.swapusage`
  to measure actual behavior; the 19 GB file by itself cannot prove that
  GPU/RAM stays within capacity. Close browsers/other heavy jobs.
- If swap or memory pressure is excessive, use `qwen3:14b-q4_K_M`
  (9.3 GB) for a **separate** run; do not silently substitute it.
  Qwen3.6 35B Q4 (about 23–24 GB) is not the first attempt on 32 GB.

## Install and verify

Ollama must already be installed and running locally.

    ollama pull qwen3-coder:30b-a3b-q4_K_M
    ollama list
    curl -s http://127.0.0.1:11434/api/tags
    system_profiler SPHardwareDataType | grep -E 'Chip|Memory'
    memory_pressure -Q
    sysctl vm.swapusage

To check actual runtime placement, start `ollama run
qwen3-coder:30b-a3b-q4_K_M` in one terminal and `ollama ps`
in another while the model is running. Prefer full GPU residency.
Exit interactive mode before the harness test.

## Private frozen prompt dataset

This runner requires the **same original six public generator-visible
prompt files and six-task suite manifest** used in the Luna experiment,
outside the repository and without scorer references or hidden factory
scripts. The generator must never see reference GLBs, Blender factories,
or grading scripts. If the two paths are unknown, locate them using:

    find "$HOME/geometry-evidence" "$HOME/Projects" \
      -name staging-manifest.json -o -name '*suites*.json'

Select the prompt root containing:
`staging-manifest.json` and
`CoffeeTable_seed0/prompt_description.txt`, plus the associated
full six-task suite JSON previously generated by
`benchmarks/catalog/select_suites.py`.

The tool checks the original six IDs, exact frozen dataset revision,
suite-manifest SHA and hashes of both public prompt files for
**every requested task before sending any model request**.

## Small two-task smoke before all six

On the operator Mac in the project Python environment:

    cd ~/Projects/3d-rendering-llm
    git fetch origin
    git switch feature/g1-ollama-32gb-smoke
    export PYTHONPATH=src
    export PUBLIC_ROOT="/absolute/path/to/previous/public/generator-smoke"
    export SUITE="/absolute/path/to/previous/suites.json"
    python3 -m geometry_harness.local_smoke \
      --public-root "$PUBLIC_ROOT" \
      --suite "$SUITE" \
      --out "$HOME/geometry-evidence/qwen3coder-30b-2-task-01" \
      --task CoffeeTable_seed0 \
      --task Bottle_seed0

This returns exit code **1** if a scene fails; this is **honest
experiment data**, not automatically a code crash. Inspect
`local-benchmark.json`, task source, safe scene-spec, logs and actual
reopened Blender geometry.

If memory and output validity are acceptable, invoke a **new**
`--out "$HOME/geometry-evidence/qwen3coder-30b-six-01"` without
`--task` to test all six frozen prompts. For each scene the tool reports
provider result, local token counters and timing, normalized labels,
safe AST acceptance and independent native Blender reopen.

No generated code is ever executed directly. All private code/meshes
stay in the operator's local evidence directory and do not enter public
GitHub or GCS automatically. Compare to the original Luna native 2/6
and deterministic name-only 5/6 counterfactual **without relabeling
either historical result**. Use the previously pinned per-task scorer,
same reference provenance and semantic/visual review in a separately
audited follow-on scoring step. Neither CPU/GPU energy nor electricity
is represented as free; `api_cost_usd=0` means no paid model API usage.

### Safety and experiment limitations

The upstream model may generate forbidden Blender APIs or unsupported
loops/expressions even when asked not to. Treat that as a real parser
FAIL, **never** automatically run model Python or relax the parser to
force a pass. A 4096-token output cap is larger than the historical
2048-token Luna cap, so record the output budget distinction when
comparing task coverage; a follow-up matched-cap experiment may be
needed. This is an internal restricted-AST/Blender test, not an official
3DCodeBench leaderboard comparison.
