# Benchmark protocol — 3D Rendering LLM

Status: **protocol planned 2026-10-27; no benchmark results exist yet in this repository.**
Owner: BH-01 benchmark data, BH-02 evaluation/reporting. Execution plan and issues: [Geometry Harness workstream](../workstreams/geometry-harness.md). Required scene/gallery evidence: [showcase contract](showcase-evidence.md).

## Scope and external references

- **Primary:** [3DCodeBench](https://github.com/gaoypeng/3dcodebench), *Benchmarking Agentic Procedural 3D Modeling Via Code* ([arXiv 2606.01057](https://arxiv.org/abs/2606.01057)). 212 object categories; text descriptions and instructions, Blender 5.0 factory references; released evaluation tasks include text-to-3D, image-to-3D, multi-turn, agent mode. The **benchmark repository's source code** is Apache-2.0; the reference categories are distributed separately via [YipengGao/3DCode](https://huggingface.co/datasets/YipengGao/3DCode), so record/check dataset + underlying Infinigen terms **before** copying references or shipping any derived artifacts.
- **Secondary realistic journeys:** [BlenderWorld](https://blenderworld.github.io/) tasks; investigate version, platform, redistribution and evaluator requirements independently and report results as a separate suite, **not** as directly comparable 3DCodeBench scores.
- **Optional geometric specialism:** [P3D-Bench](https://github.com/SpatiaOS/P3D-Bench), benchmark code MIT but reference P3D datasets have noncommercial/upstream terms. Never assume code licensing grants production use of test data.
- **Architectural reference only:** [3DCodeVerse](https://github.com/gaoypeng/3dcodeverse) executes generated 3D code, validates geometry first, renders multiple views and optionally uses a separate VLM; it is not a substitute for our own baseline.

Do not clone entire upstream repos, weights or 212 factory scripts into our source repo. Pin upstream SHA/dataset revision, store large licensed data under a separate controlled cache or GCS path, and record hashes. Make clear when external metrics require unavailable GPU/model weights on Apple Silicon. Upstream paper leaderboard comparisons are valid only if scoring, rendering, versions and inputs match.

## Test cohorts (immutable after first G1 baseline)

| Tier | Proposed size | Use | Trigger |
| --- | ---: | --- | --- |
| Deterministic smoke (G0) | 1 fixture + negative cases | Validate Blender installation, native file and writer; **not AI score** | Cheap checks + trusted Mac target |
| Public 3DCodeBench smoke | **6 task IDs** | First real AI vertical slice, quick regressions of code/geometry quality | Opt-in API runs / sampled integrations |
| Public 3DCodeBench core | **24 task IDs** | Paired A/B experiments on representative categories, including difficult objects | Approved sprint benchmark |
| 3DCodeBench full | **212 task IDs** | Generalization and release regression | Release/infrequent cost-approved run |
| BlenderWorld selected | A small separately registered subset | Scene editing, multi-object workflow, real user outcome | Independent environment; after E2E MVP |

BH-01 freezes real IDs with selection rationale, deterministic random seed where applicable, category/tier/complexity, scene types, source dataset version, permissible use and expected native format in a small committed registry (no source solutions). Stratify across geometric, furniture, organic, and more complex shapes where available. A 24-case result is not a claim of full 212-category performance. Neither tune prompts on the held-out full suite nor replace inconvenient fixtures after scoring.

## Task contract and security boundary

`TaskSpec` minimal fields: `benchmark_id`, `task_id`, `suite_revision`, `source_commit_or_dataset_revision`, `task_kind`, `input_type`, `prompt_text_hash`, `allowed_reference_media_ids`, `target_blender_version`, `usage_rights`, `scorer_profile`.

- Text-to-3D agent receives **only** user task/instructions, agreed generic tool contract and any explicitly allowed task context. It **must not** read reference factory script, answers, mesh, or scorer-private assessment.
- Image-to-3D is **a different condition** with declared external reference images; if comparing 2D generated by an agent from text, record it as *text→generated-reference→3D*, not as an image-conditioned oracle.
- Reference factories may run in sandboxed scorer context to create held-out views/meshes, but never enter generator workspace or any retrieved prompts. Generated Python is untrusted code and runs with bounded filesystem, runtime, memory/network permissions and process cleanup.
- Pin Blender 5.0 for the comparable 3DCodeBench track; alternate Blender versions are separate profiles until semantic and rendering equivalence is established.

## Evaluation record and metric semantics

Each attempt writes a manifest-consistent `EvaluationRecord` with:
`run_id, source_sha, task_id, suite_revision, strategy_arm, generator_id, generator_version, model_settings, input_type, seed, prompt_hash, tool_versions, Blender_version, OS/arch, budget, elapsed_seconds, token_usage, billed_cost_or_unknown, output_artifact_hashes, status, failure_class, geometric_checks, render_ids, visual_judge_profile, visual_score_or_unknown, baseline_run_id`.

Report **denominators** and separate metrics; never impute unknown as zero except when the metric's stated failure policy explicitly requires it:

1. **Executable scene rate:** successful process, native scene exported/saved, new-process reopen with actual Blender, required artifacts hashed.
2. **Geometry correctness:** explicitly specified parts, dimensions, bounding boxes, contacts/connectivity, self-intersections where measurable; `PASS | FAIL | UNKNOWN` for each requirement. Never claim a complete closed manifold on cases where not required.
3. **Visual criterion:** reference-based image similarity (when allowed and available), blinded multiview VLM rubric (versioned), and reviewer notes. Scores are **not** identical to objective geometric constraints; report scorer availability and judge noise.
4. **Edit preservation:** on editing tasks only: requested delta verified, unrelated objects/transforms/materials held within task tolerance, native reopen + rollback integrity.
5. **Resource outcomes:** latency to accepted output, model tokens, API dollars vs imputed notional dollars, Blender render times, peak memory if measured. `cost_per_accepted = total_cost / accepted_count` with no valid denominator -> UNKNOWN.
6. **Failure taxonomy:** provider/timeout, invalid output, script syntax, Blender crash, geometry mismatch, unsatisfied prompt, lost asset, insufficient evidence, scorer unavailable.

Artifacts: per real attempt store generated source (if permitted), `.blend`, GLB where applicable, preview PNG plus orthographic/isometric views, scoring JSON, profile, logs, assertions, manifest and `index.html` / contact-sheet. Failed attempts still appear in the gallery with FAIL/UNKNOWN and context. Preserve accepted baseline before experimental edits.

## A/B attribution policy

For arms `direct`, `structured-plan`, `direct+multiview-repair`, `2d-generated-reference`, `orthographic-layout`, `code-edit`, `typed-mcp`:

- Freeze task IDs, prompt text, model/version, Blender, scorer, budgets, render profiles and randomized seeds; the **intended variable** (extra planner/tool/reference/repair) is explicit. Maintain matched randomization and report non-equivalent inputs as distinct strata rather than as a paired win.
- Account for full wall time, cost and calls of **all** stages. In experiments with extra loops, include their extra budget as actual expenditure; optionally add a fixed-total-budget comparison to answer an efficiency question.
- Before running, choose primary hypothesis, metric, practical minimum improvement and max allowed cost/latency regression. Do not decide thresholds after looking at outcomes.
- Use paired per-task diffs, confidence intervals/bootstrap and clear sample counts for core/full. For just 6 tasks, report **descriptive smoke only**, not a generalization/significance claim. Calibrate judge A/A variability; adjudicate uncertain results by human review or more runs.
- Report raw failures (including both arms failing), accepted counts and comparisons per category. Missing score -> UNKNOWN; no fake overall composite hiding missing data.
- A sprint records **KEEP / REWORK / DROP / INCONCLUSIVE**, the run IDs, source SHA, budget used, observed failures and a next single hypothesis. Maintain prior accepted baseline.

### 2D reference ablation — predeclared distinction

| Arm | Input to 3D generator | What it tests |
| --- | --- | --- |
| A direct | prompt text | baseline without 2D |
| B generated concept | prompt + image **generated from the same prompt** | help of a learned visual prior, costs included |
| C generated orthographic/layout | prompt + generated front/side/top or structured scene layout | spatial/shape constraint prior |
| D oracle-image (optional, separate table) | externally supplied ground-truth views | upper-bound *image-conditioned* task, **not** fair text-to-3D improvement |

For scene layouts, verify semantic relationship and placement in Blender (what the lines mean), not merely polygon matching. Do not add CADCraft to any arm unless a future separately justified comparison shows an actual benefit over direct SVG/JSON/Blender outline tooling.

## Per-call model usage cost audit

For every experimental model call (including generator, planner, visual judge, retries and failed calls), preserve the append-only started/settled token ledger and immutable private GCS proof. Price inputs separately as uncached, cached reads, cache writes; output includes reasoning. If usage is incomplete or tariffs are unknown, mark result UNKNOWN and never count it as $0. An A/B comparison with untracked model calls is incomplete. See [model cost observability](model-cost-observability.md).

## CI and promotion

- **Every edit:** schema/fixture validation, cheap unit and deterministic tests; no paid API or large weight download.
- **Integration:** real bounded Blender E2E on approved runner, including newly affected negative path and prior accepted showcase; verify SHA, source/runtime versions and private GCS upload.
- **Experiment:** controlled manually authorized jobs, run with real model and pinned costs; never claim PASS on a mock.
- **Release:** full suite where licensed/runnable, compare to frozen accepted baseline, inspect galleries and at least a few native files; document remaining hardware/scorer limitations.
